# 引用定位与结构化主张：格式设计

> 状态：已实现（2026-10-30），尚未经真实运行验证。目标是从格式上消除 2026-10-30 真实运行中暴露的四类问题：改写摘录、用“…”拼接不相邻原文、主张补写原文没有的年份、一条主张合并多个事实。
>
> **实现与本设计稿的差异**（根据第二次真实运行的复盘调整）：
> 1. 新增数值标准化 [quantities.py](../vcagents/quantities.py)：亿、万、千万、million、billion、M、B，英文月份、英文数词和中文数字统一换算后比较。第二次运行 8 条未通过的核查中有 6 条是这个原因。
> 2. `subject` 不做代码检查：引用的 1–3 句常常不含主体名，且中英文名称不同。`entities` 和 `quantities` 要求按原文写法照抄，因此不需要别名表。
> 3. 推算值（如 54 亿 ÷ 7 亿 ≈ 7.7 倍）不放进结构化事实，而由“证据先行”处理：正文写出算式，代码按显示精度核对。
> 4. 已实现“证据先行” [grounding.py](../vcagents/grounding.py)：分析、对比、辩论和主席正文中的金额、比例、倍数和模型数量须标注原文证据。提交时退回一轮；剩余问题交核查员优先抽查。数值匹配不免除主体、指标、时间和口径核查。用户输入与确定性计算由现有报告测算表直接展示，已删除全局数字白名单。
> 5. 退回轮数：引用位置最多 2 轮，证据先行 1 轮，之后放行，由事后校验降级。
> 6. 没有 `quote` / `fact` 字段的旧格式数据仍按原逐字匹配校验，旧结果文件可以继续渲染和回放。

## 一、要解决的问题

现在研究员和核查员都要把原文**抄写**进 `excerpt` / `verification_excerpt`，代码事后逐字比对，对不上就降为“无法核实”。上次运行中主席核查 15 条只有 3 条通过，失败原因如下：

| 原因 | 例子 | 本设计的处理 |
|---|---|---|
| 改写摘录 | 原文“完成超千万美元天使轮，达泰资本……”，摘录写成“已完成超千万美元天使轮融资，投资方包括……” | 模型不再抄写，只给位置，原文由代码取出 |
| 省略号拼接 | “…DST Global… This month, the company…” | 引用只能是一段连续句子 |
| 补年份 | 原文“自 7 月正式上线以来”，主张写“2026 年 7 月” | 日期单列字段，必须在原文中逐字出现，或另给一处引用 |
| 一条写多个事实 | “HeyGen ARR 2 亿美元、8 个月翻倍、3000 万用户、85% 财富 100 强” | 一条主张只能有一个事实类型，数量字段最多 3 个 |

另外，现在只有事后降级，模型没有机会改正。新设计在**提交时**就校验，不通过的提交会被退回并说明原因，由模型修正后重交。

## 二、原文切句与编号

### 1. 来源编号

工具每读到一个新来源，就给它分配一个本轮内唯一的短编号：

| 来源类型 | 编号 | 例子 |
|---|---|---|
| 网页或来源库快照 | `W` + 序号 | `W3` |
| 上传资料 | `D` + 序号，加页码 | `D1:p4` |

编号和快照 ID、URL、抓取时间、SHA256 的对应关系由工具箱记录，不需要模型记忆。同一快照在本轮内只有一个编号，不同角色读到的是同一个编号。

### 2. 切句规则（代码执行，结果确定）

- 先按换行切段，再在 `。！？；!?` 后切句；英文在 `. ` 后接大写字母处切句。
- 单句超过 200 字时，在 `，,、` 处再切；仍超过 200 字的（如表格）按 200 字硬切。
- 句号按整份快照全局编号，从 `s1` 开始，所以分块阅读时编号不变。
- 切句只依赖快照文本。快照内容由 SHA256 固定，同一快照永远得到同样的编号，来源库不需要迁移。切句规则带版本号 `SEGMENTER_VERSION`，改规则时旧引用仍按旧版本解析。

### 3. 工具返回格式

`fetch_url`、`read_source`、`search_knowledge`、`read_document` 返回的正文都改成带编号的形式：

```
来源编号：W3
标题：视频 Agent Pexo 母公司完成超千万美元天使轮
URL：https://www.woshipm.com/ai/6481261.html
快照：6cbe5abccf06…  抓取时间：2026-10-30T04:07:56Z

[W3:s1] 视频 Agent Pexo 的母公司「极致上下文」完成超千万美元天使轮，达泰资本、松禾创投、视觉中国……
[W3:s2] 本轮融资将主要用于 AI Content Agent 产品研发、全球市场拓展及核心人才引进。
[W3:s3] 此前，公司曾于 2025 年 10 月获得 HT Investment 与 BV 百度风投数百万美元投资。
```

- `web_search` 返回的搜索摘要没有句号编号，因此不能被引用，和现在“搜索摘要不算原文”的规则一致。
- 每句前的编号约增加 8%–10% 的输入 token。

## 三、引用格式

模型不再提交摘录文字，只提交位置：

```json
"quote": {"source": "W3", "from": 1, "to": 1}
```

代码校验：

1. `W3` 是本轮已读来源；`s1` 到 `s1` 在本角色或本轮其他角色实际收到的正文范围内（例如 `fetch_url` 截断后面的句子不算读到）。
2. `to - from ≤ 2`，即最多引用连续 3 句。连续由编号保证，无法拼接。
3. 通过后，由代码填入摘录原文、URL、快照 ID、字符位置和 SHA256，写进结果供报告和审计使用。

## 四、结构化主张

### 1. 字段

研究员证据和核查员主张使用同一个事实对象：

```json
{
  "subject": "极致上下文",
  "fact_type": "融资",
  "statement": "完成超千万美元天使轮融资",
  "quantities": [{"metric": "融资额", "text": "超千万美元"}],
  "entities": ["达泰资本", "松禾创投", "视觉中国"],
  "date": {"text": "", "basis": "未给出"},
  "quote": {"source": "W3", "from": 1, "to": 1},
  "date_quote": null
}
```

| 字段 | 规则 |
|---|---|
| `subject` | 主体名称，必须在引用原文中出现（允许用户给定的中英文别名） |
| `fact_type` | 枚举：融资、估值、收入或 ARR、用户或客户、产品发布、团队履历、合作或订单、市场规模、其他。一条主张只能有一个 |
| `statement` | 60 字以内，只写一个事实，不能含“；” |
| `quantities` | 最多 3 个。`text` 按原文写法照抄，例如“超千万美元”“ARR 突破百万美元”，必须在引用原文中逐字出现。这样不用解析中文数词 |
| `entities` | 投资方、客户、合作方等名称，每个都必须在引用原文中出现 |
| `date.basis` | `摘录`：`date.text` 必须在引用原文中出现；`来源其他位置`：必须另给 `date_quote`，例如文章开头的发布日期；`未给出`：`date.text` 留空 |
| `date_quote` | 只用于日期，格式同 `quote`，最多 1 句 |

`statement` 中出现的阿拉伯数字仍按现有规则检查：每个数字都必须出现在引用原文或日期引用中。

用于报告的主张句由代码拼出，例如：“极致上下文完成超千万美元天使轮融资（达泰资本、松禾创投、视觉中国）”。拼法固定，所以不会悄悄补字。

### 2. 核查员额外字段

```json
{
  "target": "视频 Agent Pexo 的母公司「极致上下文」已完成超千万美元天使轮融资……",
  "source_agent": "chair",
  "fact": { "...": "同上" },
  "verdict": "属实",
  "support": "完全支持",
  "correction": ""
}
```

- `target`：被核查材料里的原句，必须是该材料文本的子串（忽略空白）。修正环节靠它定位上游，比现在按全文匹配更可靠。
- `support`：`完全支持` / `部分支持` / `不支持`。只有“完全支持”可以判“属实”或“公司口径”，这样现在“证据只支持一部分”的规则就成了字段约束。
- `verdict` 为“不实”时，`correction` 也必须由 `fact` 支持，`correction` 中的数字必须出现在引用原文中。

## 五、校验时机：提交时退回，而不是事后降级

`Agent._submission_errors` 增加一步 `toolbox.check_quotes(data)`，在模型提交时检查以上全部规则。不通过时退回给模型，例如：

```
提交需要修正：
- claims[2].quote：W3:s41 不在你本轮读到的范围内（已读 s1–s38）
- claims[4].date：“2026”没有出现在引用原文中；原文没写年份时 date.basis 填“未给出”，或用 date_quote 引用写有年份的句子
- claims[5].statement：只能写一个事实，请拆分为两条主张
```

- 模型在同一轮对话里修正，不额外调用工具。退回次数沿用现有上限，超过上限的那条主张降为“无法核实”，不让整个角色失败。
- 事后的 `verify_evidence` / `verify_fact_check` 保留，作为第二道检查，并负责写入快照信息。

## 六、对上次运行的推演

| 上次的主张 | 新格式下 |
|---|---|
| D-1 融资（改写摘录） | 引用 `W3:s1`，`quantities` 为“超千万美元”，`entities` 为三家机构，通过 |
| D-4 “2026 年 7 月上线” | 原文只有“7 月”。要么 `date.text` 填“7 月”，要么用 `date_quote` 引用写有年份的发布日期句子。补年份的写法在提交时就会被退回 |
| D-13 团队（“…”拼接） | 只能引用连续句子，须拆成“创始人”和“关键成员”两条 |
| D-15 Higgsfield（“…”拼接） | 估值、融资额和 ARR 分属不同句子，须拆成 2–3 条，每条各自引用 |
| 复查时的“来源未读取” | 来源编号在全轮共享，研究员读过的 `W5` 核查员可以直接引用 |

改写、拼接和补年份这三类问题在提交时就会被退回。剩下没法核实的，只会是原文本身没有写到的事实，这时“无法核实”就是正确结论。

## 八、风险与验证

- **模型写错句号**，例如差一位：内容检查会发现数量或机构名不在引用句中，提交时退回让模型修正。
- **便宜模型不适应位置格式**：公司研究员用的是 DeepSeek Flash。上线前先用 [evaluation/fact_checker_smoke.py](../evaluation/fact_checker_smoke.py) 一类的小样本测试研究员和核查员各自的提交成功率，再跑完整流程。
- **PDF 和表格切句质量差**：硬切 200 字可以保证能引用，但可能切在半个数字中间。表格类来源需要单独测试。
- **仍然不能证明语义支持**：位置引用保证原文真实，`support` 字段仍是模型判断。需要的话可以加一个便宜模型做独立的“是否支持”判断，作为后续选项。

建议的验证顺序：离线测试 → 用上次运行的已归档快照做回放 → 小样本真实调用（约 $0.1）→ 完整真实运行（约 $4–5）。
