# 投研平台技术栈优化建议

空库重建测试漏掉了四份子目录报告。建议保留现有四个模块、五个 Agent，先修复归档，再按使用场景扩展。

| 优先级 | 建议 | 验收方法 |
| --- | --- | --- |
| 1 · SQLite 归档与证据 | 从 `outputs/` 和 `output/pdf/` 递归读取归档清单。按报告版本关联核心结论、证据编号、原文位置和审计结果。PDF 与 Markdown 保存在原目录。 | 用现有四版报告从空库重建，四版均可打开。重复重建无重复记录。抽查一条护城河判断，能定位当时引用的原文。 |
| 2 · 后台任务与成本 | 网页提交后返回任务编号。后台按阶段保存产物、输入版本和已知费用，保留主动取消功能。 | 在研究完成、定稿开始前重启，能复用已核验材料。付费调用结果未知时标记待核对，避免盲目重发。 |
| 3 · Docker Compose | 团队部署时，让网页和后台任务使用同一镜像，固定依赖和中文字体，持久化数据库及报告目录。 | 在新机器导出中文 PDF，检查字体和页数。重建容器后仍能打开历史报告。 |
| 4 · MCP 资料接入 | 有授权资料室时，先接入“查找文档”和“读取指定版本及页段”两个只读工具，复用已有来源登记与核查流程。 | 同一份 BP 更新后，审计仍能打开旧报告引用的版本和页码。 |

数据层同步记录研究记忆的入库数与跳过原因。出现跨主机共享写入或持续写锁争用时，再评估 PostgreSQL。
