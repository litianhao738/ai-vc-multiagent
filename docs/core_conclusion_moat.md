# 核心结论收敛与护城河复核

这次调整沿用四主Agent和原投资报告框架，不新增Agent、必填JSON字段或固定措辞校验。目标是让研究形成一个有证据、有边界、可被推翻的首要判断，不能保证模型零误判、护城河永久有效或长期投资一定获利。

## 报告围绕什么展开

每家公司用现有 `standout.point` 提出最突出的一点。重点公司的 `top_pick_thesis` 第一条（T1）是报告的首要投资逻辑，`core_answer`、标题与行动建议围绕它展开；其余最多两条是支持条件或限制，避免写成几个无关的投资故事。六个长期竞争力维度用于检验主判断，不要求各自提出一种护城河。

主判断应回答以下问题：

1. 相对最接近的竞争者，公司最突出的一点是什么？没有明显优势时可以如实判断。
2. 它如何带来用户收益，并转为持续付费、成本优势或公司能获取的价值？
3. 竞争者为什么难以复制或替代？关键资源由公司、上游还是平台控制？
4. 证据目前支持产品亮点、正在形成的护城河，还是已有持续性证据的护城河？不能直接把增长、融资或单次效果当作长期壁垒。
5. 优势依赖哪些条件，哪些可观察的反证会改变判断？重点考虑相关的竞品复制、降价、上游变化、平台依赖及用户迁移。
6. 在这些条件下，估值、稀释、资金消耗、后续融资、退出及下行情景是否支持当前投资行动？商业质量不能替代价格和回报分析。

允许“护城河尚未证实”成为核心结论。这表示证据尚不足，不自动等于公司没有优势。用户未提供持有期时保留未知，不编造持续年限、回报保证或失效阈值。

## 在哪里生效

- 总控规划、决策和编辑提示分别限定研究主线、首要逻辑及成稿一致性；分析主Agent检验优势形成与价值获取机制。
- `vcagents/schemas.py` 仅更新现有字段的说明，数据结构、条数上限和原校验接口保留。
- [护城河复核提示](../prompts/moat_review.md) 经 `MainAgentPipeline._reasoning_context()` 加入现有独立推论审计；初审和发布修复后的复查均使用它，并记录提示词内容哈希。
- 沿用现有 T1、C1、A1、V1 等目标的版本与覆盖检查。模型发现依据不足、条件未写入正文或证据冲突时，进入原定向修复与复查流程；仍存在阻塞问题则保留草稿。
- 不新增标点、单位写法或固定短语退回条件；原“退回必要性复核”职责保持不变。

## 保证边界与验证

代码可以检查审计目标是否覆盖、版本是否匹配，以及已识别的问题是否进入修复和发布检查；结论是否真正聚焦、证据是否足以证明长期优势，仍依赖研究材料和模型判断，不能由字段或提示词保证。
